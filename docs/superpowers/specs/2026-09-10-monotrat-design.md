# monotrat — дизайн

Дата: 2026-09-10
Статус: погоджено («роби» після секції 1; решта — рекомендовані рішення)

## 1. Що це

Публічний легкий сайт у візуальній мові дашборду monobank (https://monobank.ua/dashboard).
Користувач вставляє персональний токен monobank API — сайт завантажує транзакції
всіх рахунків і показує розширену аналітику витрат і доходів: категорії, мерчанти,
календар і ритми, прогноз і порівняння з минулими періодами, підписки й аномалії.

Неофіційний проєкт, не пов'язаний з monobank. Без логотипа й кота mono — лише візуальна мова.

### Цілі
- Усе працює в браузері; токен ніколи не йде нікуди, крім `api.monobank.ua`.
- Дашборд оживає за ~1 хв після вставки токена й «дозріває» у фоні до 12 місяців історії.
- Повторні візити миттєві (кеш) і дозавантажують лише нове.
- Мова інтерфейсу — лише українська.

### Не-цілі (v1)
- Бекенд, акаунти, синхронізація між пристроями.
- Ручне редагування категорій, бюджети, експорт.
- Історичні курси валют (використовуємо поточний курс mono — див. 3.4).
- Логотипи мерчантів (буквені аватари кольору категорії).
- Світла/темна тема на вибір — одна тема як у mono (світла сторінка, чорні плитки).

## 2. Архітектура

Статичний SPA: **Vite + React 19 + TypeScript + Tailwind CSS 4**, деплой на **Cloudflare Pages**.
`api.monobank.ua` віддає `access-control-allow-origin: *` і дозволяє заголовок `x-token`
(перевірено), тож бекенд не потрібен.

Модулі (кожен має одну відповідальність і тестується окремо):

| Модуль | Відповідальність | Залежить від |
|---|---|---|
| `src/api/` | Типізований клієнт mono: `getClientInfo`, `getStatement`, `getCurrency`; помилки як `MonoApiError { status }` | `fetch` |
| `src/store/` | IndexedDB (через `idb`): транзакції, рахунки, курси, карта покриття; in-memory фолбек | `idb` |
| `src/sync/` | Черга завантаження: план вікон, лімітер, ретраї, пагінація, відновлення | `api`, `store` |
| `src/analytics/` | Чисті функції `NormalizedTx[] → метрики`. Без React, без IO | — |
| `src/demo/` | Детермінований генератор синтетичних транзакцій (демо-режим і розробка) | `analytics` типи |
| `src/ui/` | Екрани, віджети, SVG-графіки | усе вище |

Стан застосунку — невеликий власний стор (`useSyncExternalStore`) без сторонніх бібліотек.
Графіки — власні SVG-компоненти; `d3-shape` лише для геометрії дуг/ліній.
Шрифти self-hosted через `@fontsource`: **Geologica** (заголовки, великі числа, текст)
і **Roboto Mono** (точні числа, відсотки, номери рейтингу).

## 3. Дані

### 3.1 Monobank API (перевірено в документації)
- `GET /personal/client-info` — рахунки (`accounts`), банки (`jars`), `managedClients`. Ліміт: 1 раз / 60 с.
- `GET /personal/statement/{account}/{from}/{to}` — `account` = id рахунку **або банки**.
  Макс. вікно 31 доба + 1 година (2 682 000 с). Ліміт: 1 раз / 60 с.
- `GET /bank/currency` — публічні курси (`rateBuy`/`rateSell`/`rateCross`).
- Суми — у мінімальних одиницях валюти (копійки), `amount` у валюті рахунку.
- Захисна пагінація: якщо відповідь містить ≥ 500 елементів, догружаємо той самий
  проміжок від `from` до `time` найстаршої отриманої транзакції.

### 3.2 Порядок завантаження
Вікна — календарні місяці за часом Europe/Kyiv: поточний (частковий) + 12 попередніх = 13 вікон
(13-й потрібен для «той самий місяць торік»).

Черга за пріоритетом:
1. `client-info` (кешується на сесію).
2. Для місяця `m = 0..12` (0 — поточний): спершу всі картки (`accounts` без ФОП), потім ФОП-рахунки, потім банки.

Лімітер: один запит до mono не частіше ніж раз на 61 с. На `429` — пауза 65 с і повтор
того ж запиту (без ліміту спроб, поки вкладка відкрита). Інші 5xx/мережа — 3 спроби з
паузою 61 с, далі вікно позначається `failed` і черга йде далі (кнопка «Спробувати ще»).

Прогрес: «Завантажено N з 13 міс · ще ~X хв» (X = залишок запитів × 61 с) +
зворотний відлік до наступного запиту.

Дашборд рендериться після першої успішної виписки й оновлюється після кожної наступної.

### 3.3 Кеш і відновлення
IndexedDB `monotrat`:
- `transactions` (key `id`, index `accountId`, `time`) — сирі елементи виписки + `accountId`.
- `accounts` — нормалізовані рахунки й банки з `client-info`.
- `coverage` (key `${accountId}:${YYYY-MM}`) — `{ status: 'complete' | 'partial' | 'failed', fetchedUntil }`.
- `meta` — курси (`fetchedAt`), `lastClientInfoAt`.

Минулі місяці після успіху — `complete` і більше не запитуються. Поточний місяць —
`partial`; при кожному візиті догружаємо `fetchedUntil → now` (1 запит на рахунок).
Якщо в браузері вкладку закрили посеред завантаження і токен «запам'ятали» —
при наступному візиті черга продовжується з непокритих вікон.

Лише одна вкладка синхронізує: `navigator.locks.request('monotrat-sync')`; інші читають кеш.
Прихований таб: таймери Chrome у фоні не частіше ніж 1/хв — нашому ритму це не шкодить.

### 3.4 Нормалізація
Кожна транзакція → `NormalizedTx`:
```ts
{
  id, accountId, time, description, comment, mcc, hold,
  amountUah: number,        // копійки UAH, зі знаком
  cashbackUah: number,      // нарахований кешбек, копійки UAH
  kind: 'expense' | 'refund' | 'income' | 'internal' | 'cashbackPayout',
  category: CategoryId,     // для expense/refund; для income — 'income'
  merchantKey: string,      // нормалізований ключ для групування
  merchantLabel: string,    // людська назва
}
```
- **Валюта:** рахунки не в UAH перераховуються за поточним курсом mono
  (`rateCross`, або середнє `rateBuy`/`rateSell`). На дашборді примітка «валютні рахунки — за поточним курсом».
- **Внутрішні перекази (`internal`):** (а) парування: −X на рахунку A і +X′ на рахунку B
  (своїх), |Δt| ≤ 180 с, |X − X′| ≤ 1% в UAH; (б) `counterIban` збігається з IBAN власного рахунку;
  (в) шаблони опису (`/^(з|на) (чорн|біл|залізн|платинов|гривнев|доларов|євро|фоп)/i`,
  назви власних банок з `client-info`). Внутрішні не входять у витрати/доходи;
  поповнення **власних** банок — окрема метрика «Відкладено».
- **Виплата кешбеку (`cashbackPayout`):** шаблон опису (`/кешбек|cashback/i`) на додатній сумі. Не дохід.
- **Повернення (`refund`):** додатна сума з «торговим» MCC (не 4829/6010/6011/6012/6536–6540)
  → зменшує витрати своєї категорії.
- **Холди:** рахуються, з позначкою в списках.
- **Перекази людям** (MCC 4829/6536–6540, від'ємні, не internal) — категорія «Перекази».
  Глобальний перемикач «Не враховувати перекази» (за замовчуванням **вимкнений** — перекази враховуються).

### 3.6 Мерчанти
`merchantKey` = опис → нижній регістр → без лапок/`№`/номерів філій і хвостових цифр
→ без суфіксів міста/країни → схлопнуті пробіли. `merchantLabel` — найчастіший
оригінальний опис у групі. Аватар — перша літера на крузі кольору категорії.

## 4. Аналітика (`src/analytics/`)

Усі функції чисті: `(txs: NormalizedTx[], opts: { period, now, includeTransfers }) → результат`.
Період — календарний місяць (за замовчуванням поточний; перемикач серед завантажених місяців).
Частина віджетів використовує всю завантажену історію (позначено «історія»).

### 4.1 Підсумки (`summary.ts`)
Витрачено, Отримано, Кешбек нараховано (Σ `cashbackUah`), Відкладено в банки, Нетто —
за період, з дельтою до попереднього місяця. Кількість операцій, середній чек.

### 4.2 Прогноз і порівняння (`forecast.ts`, `compare.ts`)
- **Прогноз витрат на кінець місяця** = витрачено_досі + очікувані_регулярні (підписки з
  `nextDate` у решті місяця, ще не списані) + `rate × днів_лишилось`, де `rate` — змінні
  (нерегулярні) денні витрати: `0.5 × (MTD_змінні / днів_минуло) + 0.5 × (усічене середнє
  денних змінних витрат за останні 90 днів, без верхніх 5%)`. Якщо історії < 30 днів — лише MTD.
  Діапазон: `± σ_денних × √днів_лишилось`.
- **Прогноз доходів** = отримано_досі + очікувані регулярні надходження (той самий алгоритм
  регулярності, що для підписок, на доходах), ще не отримані цього місяця.
  Поруч — середній дохід за 3 міс.
- **Порівняння:** «на цей день» минулого місяця (кумулятивно на той самий день),
  середнє за 3 попередні місяці, той самий місяць торік (якщо завантажено).
- **Кумулятивний графік:** лінія поточного місяця vs минулий vs середнє 3 міс + пунктир прогнозу.
- **Кешфлоу (історія):** стовпці доходи/витрати по місяцях + лінія нетто.

### 4.3 Категорії (`categories.ts`)
Частки категорій за період (сума, %, к-сть), дельта кожної до середнього за 3 міс,
«Найбільше зросли / впали» (≥ 500 ₴ і ≥ 30% різниці).

### 4.4 Мерчанти (`merchants.ts`)
Топ-10 за сумою і за кількістю (перемикач), середній чек, частота («раз на N днів», історія),
нові мерчанти цього місяця (не зустрічались раніше в історії), топ-5 у кожній категорії.

### 4.5 Календар і ритми (`calendar.ts`)
- Теплова карта днів місяця + топ-5 найвитратніших днів (з головними покупками дня).
- Матриця день тижня × година (історія) — сума й кількість.
- Середня денна витрата: будні vs вихідні.
- Дні без витрат (без expense-операцій) і найдовша серія за період.

### 4.6 Підписки й регулярні платежі (`recurring.ts`)
Групуємо expense за `merchantKey`. Кандидат, якщо ≥ 3 операції (або ≥ 2 для річних),
медіанний інтервал ≈ 7±2 / 30±4 / 365±15 днів, коефіцієнт варіації інтервалів < 0.25,
суми в межах ±15% від медіани. Результат: мерчант, сума, періодичність, наступна очікувана
дата, еквівалент на місяць, на рік; позначка «подорожчала», якщо остання сума > попередньої на > 5%.
Підсумок «Регулярні платежі — X ₴/міс».

### 4.7 Аномалії й великі покупки (`anomalies.ts`)
- Незвична операція: сума > max(3 × медіана мерчанта, p95 категорії) і > 500 ₴.
- Незвичний день: денні витрати > медіана + 3 × MAD (історія).
- Сплеск категорії: прогноз категорії на місяць > 1.5 × середнє 3 міс і > 1 000 ₴.
- Топ-10 найбільших покупок періоду.

### 4.8 Цікаві факти (`insights.ts`)
Набір правил; кожне повертає `Insight | null` (`emoji`, заголовок, значення, пояснення).
Показуємо ті, що спрацювали: найбільша покупка, найвірніший мерчант (найбільше різних місяців),
«нічні витрати» (частка після 22:00), улюблений день тижня для витрат, кава/фастфуд
(к-сть операцій MCC 5814 і середній чек), кешбек за рік, «витрати після зарплати»
(середня денна витрата 7 днів після найбільшого надходження vs інші дні).

## 5. UI

### 5.1 Візуальна мова (з дашборду mono)
- Сторінка світла `#f6f6f6`/`#fff`, текст `#000`; блоки — **чорні плитки** `#000`, радіус **40px**
  (32px на мобільному), внутрішні відступи ~24px.
- В плитці: іконка в квадраті `#161616` з радіусом 16px, яскравий колір іконки →
  велике число (Geologica Bold, «24,3 тис») → підпис (Geologica SemiBold, білий) →
  точне число **Roboto Mono** кольором акценту плитки («24 318,40 ₴»).
- Акценти (семпльовані зі скриншота mono): лайм `#6dc106`, рожевий `#ff54bf`,
  м'ятний `#50ffd8`, сталево-блакитний `#78b7d0`, салатовий `#7cff6b`, червоний `#ff585b`
  (бренд-червоний сайту `#fa5255`), фон іконки `#161616`.
- Блок категорій — чорний з радіальним сяйвом `#042418` у центрі → `#000` по краях;
  список з відсотками моно-шрифтом, активний рядок фон `#0d3128`, текст `#22a574`;
  справа кільце (неактивні сегменти `#152b23`), активний сегмент `#2fbe92` зі світінням,
  іконка категорії в центрі.
- Рейтинги як «Топ-10 продавців»: `01` сірим моно, аватар, назва, сума моно праворуч.
- Перемикачі — «таблетки» (активна чорна з білим текстом).
- Заголовки секцій — Geologica Bold ~24px, чорні, над плитками.
- Сітка: 4 колонки ≥ 1100px, 2 — планшет, 1 — мобільний (плитки горизонтальні, як у mono mobile).

### 5.2 Екрани
1. **Онбординг.** Заголовок «Куди ж поділись гроші?», пояснення, поле токена, галочка
   «Запам'ятати на цьому пристрої», кнопка «Показати аналітику», інструкція як отримати
   токен (`api.monobank.ua` → QR у застосунку → скопіювати), блок «Чому це безпечно»
   (токен лише читає; запити йдуть прямо в mono — перевірте в DevTools; нічого не зберігаємо
   на серверах; немає сторонніх скриптів), кнопка **«Подивитись демо»**.
2. **Дашборд** (порядок секцій):
   1. Шапка: `monotrat`, пігулка статусу синхронізації, перемикач місяця, меню
      (перемикач «Не враховувати перекази», «Вийти і стерти дані»).
   2. Заголовок «Дашборд» + рядок-підзаголовок.
   3. 4 плитки: Витрачено · Отримано · Кешбек · Відкладено (з дельтою).
   4. Прогноз: 2 плитки (витрати / доходи на кінець місяця) + кумулятивний графік.
   5. Категорії: кільце + список, «зросли/впали».
   6. Мерчанти: топ-10 з перемикачем «Сума / Кількість», нові мерчанти, сітка «топ-5 у категорії».
   7. Календар і ритми: теплова карта місяця + топ днів; матриця тиждень × година;
      плитки «будні vs вихідні», «днів без витрат», «найдовша серія».
   8. Регулярні платежі.
   9. Аномалії й найбільші покупки.
   10. Кешфлоу по місяцях.
   11. Цікаві факти.
   12. Футер: «Неофіційний проєкт, не пов'язаний з monobank» + приватність.

Віджети, яким бракує даних (напр. «торік»), показують стан «Дозавантажуємо історію…»
з прогресом, а не порожнечу.

## 6. Помилки
- `401/403` на будь-якому запиті → токен невалідний: стираємо токен, повертаємо на онбординг з повідомленням.
- `429` → «monobank просить почекати» у статусі, повтор через 65 с.
- Офлайн → пауза черги, відновлення на подію `online`.
- IndexedDB недоступна (приватний режим) → in-memory стор + банер «дані не збережуться».
- Помилки рендера віджета — `ErrorBoundary` на кожну секцію, решта дашборду працює.
- «Вийти і стерти дані» → видаляє БД, `localStorage`/`sessionStorage`, скидає стан.

## 7. Безпека й приватність
- Токен: `sessionStorage` за замовчуванням; `localStorage` лише з галочкою «Запам'ятати».
- CSP через `public/_headers` (Cloudflare Pages): `default-src 'self'; connect-src https://api.monobank.ua;
  img-src 'self' data:; style-src 'self' 'unsafe-inline'; font-src 'self'; frame-ancestors 'none'`.
- Жодної сторонньої аналітики/скриптів; шрифти self-hosted.
- Токен ніколи не логується і не потрапляє в URL.

## 8. Тестування
- **Vitest** unit: нормалізація (internal-парування, refund, cashback, валюта), MCC → категорія,
  мерчант-ключі, summary, прогноз, порівняння, календар, recurring, anomalies, insights — на фікстурах.
- **sync:** fake timers + мок `fetch`: порядок черги, інтервал 61 с, 429-повтор, пагінація ≥ 500,
  відновлення з `coverage`, 401 → вихід. Стор — з `fake-indexeddb`.
- **UI smoke:** Testing Library рендерить дашборд на демо-даних без помилок.
- **Ручна перевірка:** `vite dev` у демо-режимі + скриншоти headless Chrome (desktop 1440 і mobile 390).
